What: rules LEARNED as tensor-logic programs instead of only fitted from hand-written templates. No language model.
Switches on AgentConfig (default off = old behaviour, checked action for action against the backup on Locksmith,
Ghost Twin, Warehouse, 2 seeds x 500 actions, and the live touch arm reproduced the morning sweep exactly):
  use_tl        relational perception + learned rules added to the proposer
  tl_templates  False = hand-written templates OFF (the "tl_only" arm; the explorer's mover then comes from the
                learned program)
  tl_plan       explorer plans by forward-chaining reachability (tl/plan.py) instead of its breadth-first search
Arms in game_sweep: touch_tl (touch + use_tl), tl_only (use_tl, templates off).
How: tl/relations.py turns each step into relations over objects (colour, type, controlled, common-fate group,
  colours ahead in each move direction, run into / stood on / next to / clicked / moved along with the controlled
  piece, changed last step, own history, previous run's tape). tl/learner.py: six join shapes feed one softmax per
  object (own x action; ahead; own relation; linked object = switch->door; own history with a learned lag; previous
  run with a learned lag = the ghost). Gradient fit with an L1 (description length) step; an equation switches on
  when its zero-weight gradient beats its price (also on surprise spikes); weights thresholded at T=0, pruned (a
  weight must fix >= 2 decisions), exported as frozen TLRules (tl/rule.py) split by what they predict (moves =
  decision rules; each other kind of change = a small add-on). The existing MDL posterior prices and selects them.

1. WHAT THIS IS
========================================================================================================
An active-inference / FEP-inspired agent for ARC-AGI-3 games. It keeps a posterior over rule sets
(minimum-description-length prior + per-part likelihood), explores with an object-contact explorer and
EBUL curiosity (entropy from the last EBUL layer, patch codes), and is being moved toward SOFT COMPUTING:
phasor vectors / fractional power encoding / hyperdimensional computing (vector symbolic architecture).
Explicit code stays for search and Bayesian bookkeeping; soft pieces must beat the explicit piece they
replace, on their own number, or they don't go in.

Run everything from ~/GitHub/arc-3/ARC3-Inference with .venv/bin/python (Python 3.12):
  python -m rulediscovery1__fepInspired.<module>
Exact local simulators: docs/static/games/src/<game>-<build>/ on vendor/arcengine-0.9.3 (env.py GameEnv).

  - Locksmith: level one cleared in every seed, same speed, with and without.
  - Ghost Twin and Warehouse: nothing cleared either way.
Prediction (fair measure = "rules' gain": counts-only nats minus posterior nats on the SAME steps;
raw posterior nats are NOT comparable across arms because the arms walk different paths):
  - Ghost Twin: vector version better on every seed.
  - Warehouse: better on most seeds.
  - Locksmith: level.
  - (Correction of an earlier channel message: Ghost Twin looked "a bit worse" only on the raw number;
    the extra Ghost Twin game over is noise.)
Which piece:
  - Common-fate grouping (parts that move together = one object) carries almost all the gain on
    Ghost Twin and Warehouse.
  - Soft wall map: barely moves things live; offline it predicts blocked moves better than the colour
    rule on all three games, but on Warehouse with more false walls.
  - Ghost tape rule: in the rule set now, but live it never mattered. The agent's own runs are too
    short: by the time it spots a copying object the copied run is used up, so the tape can only say
    "stands still", which the counts already cover. (Corrects the channel note that it "earns its keep
    with the grouping on".)
  - Revocable grouping did not help Warehouse; the gain comes from grouping by object, not from undoing.
What got worse: one more Ghost Twin game over (noise-sized); Locksmith plays about three times slower
  to run, because a lost life is mistaken for a rewind by the tape piece.
Next fixes: try permanent grouping live; let the tape rule claim "the ghost stays put" and decide
  sooner; stop counting a respawn as a rewind.
Why no levels: what blocks clears is planning and budget (step bar / timer, survival), not perception.
